# ארכיטקטורה

```
web/ (React, RTL)  ──/api──▶  server/app.py (FastAPI)
                                 ├─ /auth   pt_agent.api.auth   אימות, תפקידים, סשנים
                                 ├─ /cc     cc.routes           מרכז הבקרה
                                 │    ├─ connectors/  GitHub · Vercel · Supabase · n8n (קריאה בלבד, allowlist שדות)
                                 │    ├─ sync.py      זהות נכס/אירוע, סדר לפי זמן מקור, היעלמות, תיבת מיון, התראות
                                 │    ├─ agents.py    ריצה בקריאה-בלבד, Anthropic SDK או סיכום דטרמיניסטי, אומדן עלות
                                 │    └─ secrets.py   Fernet; הטוקן לא חוזר מה-API
                                 └─ /pt     pt_agent.api.app     סקרי אבטחה (sub-app)
                               pt_agent.storage  Store אחד: Postgres / Supabase REST / זיכרון
                               Postgres (Supabase)  29 טבלאות, organization_id בכולן, RLS מופעל
```

## גבולות

- **ארגון** הוא הדייר. **מרחב** הוא גבול ההרשאות בתוך הארגון (אפיון v2 סעיף 2).
  כל קריאה/עדכון ב-`cc` עובר `require_workspace` לפי תפקיד (admin/editor/viewer);
  מנהל ארגון הוא admin בכל המרחבים שלו.
- שיוך נכס לפרויקט מותר רק באותו מרחב. מפתח ספק לסוכן חייב להיות מאותו מרחב.
- סודות: מוצפנים ב-`data.secret_enc`, מוסתרים ב-API, נדרשים רק בשרת.
- סוכנים: `tools=["catalog.read"]` בלבד בגרסה זו. פעולות כתיבה הן שלב המשך
  עם יכולת ייעודית ואישור.

## קליטה (sync)

1. `verify()` לפני שמירה. הכיסוי בפועל (מלא / חלקי / מלאי בלבד / חסום) נשמר על החיבור.
2. נכס = (מרחב, ספק, סוג, מזהה חיצוני). אירוע = (מרחב, חיבור, מזהה חיצוני) כולל ניסיון ריצה.
3. אירוע מאוחר מעדכן תמונת מצב רק אם חדש יותר לפי זמן המקור.
4. נכס שלא חזר בסנכרון **מלא** מסומן "הוסר במקור"; סנכרון חלקי לא מוחק.
5. תיאור ידני ושיוך ידני שורדים סנכרון.
6. כשל בייצור על נכס משויך → התראה. אין סנכרון תקין 45 דקות → התראה.
