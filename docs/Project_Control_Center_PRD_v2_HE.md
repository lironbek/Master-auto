# מרכז הבקרה לפרויקטים, סשנים ואוטומציות
**אפיון מוצר ויישום | גרסה 2.0 | 7 בנובמבר 2026**

## 1. מטרת המוצר

מרכז בקרה פרטי בעברית שמציג את הפרויקטים של לירון, את הכלים שמרכיבים כל פרויקט, את העבודה האחרונה שנעשתה ואת החריגות שדורשות תשומת לב. בתוך פחות מדקה אפשר להבין מה קיים, מה כל רכיב עושה, איפה הוא רץ, מתי התקבל ממנו מידע ומי אחראי עליו.

ניהול במרכז הבקרה כולל חיבור מקורות, סנכרון, שיוך לפרויקטים וסשנים, סיווג חשיבות, הגדרת התראות וניהול הרשאות. הפעלת סוכנים וניהול ריצות שלהם מתבצעים במרכז הבקרה. כלים מחוברים נפתחים ישירות מהפרויקט. שינוי קוד, פריסה ושינויים בתשתית מתבצעים בכלי המקור או באמצעות פעולה ייעודית שאושרה לפי מדיניות הסוכנים. תצוגת הדמו היא יישום נפרד עם נתונים סינתטיים.

הצילום המצורף שימש השראה לתצוגה. דף הדמו החיצוני לא היה זמין לבדיקה. המספר 77 משמש להמחשת קנה המידה בסיפור ההשראה. המערכת תחשב את המספרים מהקטלוג בפועל.

## 2. היררכיה ומונחים

| רמה | הגדרה | דוגמה להמחשה |
|---|---|---|
| מרחב | גבול הרשאות ונתונים. כל מרחב מחבר חשבונות שאושרו עבורו | עבודה בקומקס, פרויקטים פרטיים, מרחב לקוח נפרד לפי צורך |
| פרויקט | יחידת הניהול הקבועה. מכילה נכסים, סשנים ופעילות | שילוט COMAX, BuildFlow, קליניקת אפרת |
| סביבת הרצה | מאפיין של נכס או אירוע, נפרד מסטטוס ומסשן | פיתוח, בדיקות, Preview, Production, לא מסווג |
| נכס | פריט מזוהה במקור אחד, עם קישור וסטטוס משלו | ריפוזיטורי, פרויקט Vercel, פרויקט Supabase, Workflow, בוט |
| סשן עבודה | פרק עבודה עם מטרה, בעלים ותוצר אפשרי. נשמר תחת פרויקט אחד ויכול לקבץ אירועים מכמה כלים | ״סידור משתני מבצע בשילוט״ |
| ריצה / פריסה | ביצוע בודד שהתקבל ממערכת מקור. מופיע בציר הפרויקט ויכול להיות משויך לסשן | GitHub Actions run, פריסת Preview, ריצת n8n |

**הנחת אפיון לגבי סשנים.** סשן הוא פרק עבודה בפרויקט, לרבות סשן פיתוח ב־Claude Code או Codex. שיחה, PR או ריצה יכולים להיות מקושרים אליו. אפשר לגלוש גם לפי סשנים מכל הפרויקטים, בהתאם להרשאות.

### מחזור חיים של סשן

1. פותחים סשן מתוך פרויקט או קולטים אירוע התחלת סשן מהתקנה מאושרת של כלי הפיתוח. סשן ידני דורש כותרת, מטרה ובעלים. באירוע אוטומטי הכותרת יכולה להתחיל משם הריפוזיטורי והענף, ללא תוכן השיחה.
2. סטטוס הסשן הוא ״פתוח״, ״ממתין״, ״הושלם״ או ״בוטל״. מצב כלי הפיתוח מוצג בנפרד. סגירת ה־CLI יכולה לסיים את הסשן הטכני ולהשאיר את העבודה פתוחה.
3. אירוע משויך אוטומטית כשקיים מזהה סשן מפורש או כלל שמור עם התאמה יחידה. PR, ענף ו־commit הם אותות להצעת שיוך. במקרים עמומים האירוע מוצג בפרויקט עם הצעת שיוך, בלי לשייך אוטומטית לפי שעת הפעילות.
4. בסגירה מוסיפים תוצר, קישור והמשך טיפול. אפשר לפתוח מחדש תוך שמירת היסטוריה. סשן ללא אירועים במשך זמן שהוגדר מסומן ״ללא פעילות לאחרונה״.

| חיבורים | ספק, חשבון או ארגון, כיסוי, הרשאות, סנכרון אחרון, ניסיון אחרון וסיבת כשל | חיבור, בדיקת הרשאות, סנכרון כעת, התחברות מחדש וניתוק |
| תיבת מיון | נכסים חדשים, חוסר התאמה, כפילות אפשרית ומקור שנעלם | אישור שיוך יחיד או קבוצתי, יצירת פרויקט, דחיית הצעה, סימון נכס משותף |
| התראות והיסטוריה | כשל אחרון, כשלים חוזרים, עיכוב בסנכרון, שינויים בשיוך ובהרשאות | אישור טיפול, השהיית התראה והגדרת כללים בתוך המרכז |

עיצוב RTL עם תפריט ימני, תצוגת כרטיסים ורשימה, וחיפוש לפי שם פרויקט, שם נכס, ספק או מזהה. כתובות, שמות ריפוזיטוריז ומזהי פריסה מוצגים משמאל לימין. לכל סטטוס תווית וסמל לצד הצבע. פתיחת המסך משחזרת את סינון המשתמש, בכפוף להרשאות העדכניות.

## 4. מקורות מידע ומחברים

כלי שמחובר כיום ל־ChatGPT, ל־MCP או ל־IDE יכול לשמש לבדיקת היתכנות. המוצר העצמאי צריך הרשאה מתאימה משלו מול הספק כדי לסנכרן ברקע. בעת הקמה בעל המרחב בוחר את הארגונים, החשבונות והמופעים לחיבור. רשימת החשבונות בפועל, השיוך שלהם והיקף ההרשאות ייקבעו במסך ההקמה.

| מקור | מה מייבאים | דרך חיבור ומגבלות | שלב |
|---|---|---|---|
| GitHub | ריפוזיטוריז נבחרים, PRs ומצב ריצות Actions | GitHub App עם Metadata, Pull Requests ו־Actions לקריאה לפי התכונות שנבחרו. Webhooks חתומים לפי צורך | MVP |
| Vercel | פרויקטים, פריסות, סביבה, סטטוס, קישור ומזהה commit כאשר זמין | API של Vercel בהקשר החשבון או הצוות שנבחר. מסננים שדות מזהים ומצב. אם האסימון רחב מהנדרש, מתעדים את הפער ומחייבים בחירת בעל המרחב | MVP |
| Supabase | ארגון, project ref, שם, אזור וסטטוס פרויקט לפי השדות הזמינים | Management API בהרשאה מתאימה. התוצר הוא מטא־דאטה תשתיתי. מצב הפרויקט מוצג בנפרד מבריאות האפליקציה | MVP |
| n8n | Workflows, סטטוס פעילות וריצות עם מזהה, זמן ותוצאה | Public API למופע שנבחר. יכולות תלויות גרסה, תכנית והרשאה. אם חסרה הרשאת executions, מציגים ״מלאי בלבד״ או קולטים אירוע מסוכם מ־Webhook ייעודי | MVP אם קיים מופע מאושר |
| Claude Code / Codex | מזהה סשן, התחלה וסיום כשהכלי חושף אותם, ריפוזיטורי/ענף ותוצר מקושר | Hooks או מדווח מקומי שאושר והותקן בסביבה. בודקים תמיכה לפי מוצר וגרסה. אפשר לצרף קישור או לפתוח סשן ידני כחלופה. כל סביבת הרצה מדווחת על עצמה | פיילוט אחרי MVP |
| ChatGPT / אוטומציות מתוזמנות | קישור, שם, סטטוס ותזמון במידה שמקור מורשה מספק אותם | קישור ידני או ייבוא נבחר כברירת מחדל. מחבר אוטומטי רק כשאומתה גישה נתמכת עבור החשבון וסוג הנתון | שלב 2 |
| Make / Zapier / Pipedream | קטלוג תרחישים ומטא־דאטה של ריצות לפי יכולות המקור | בוחנים API והרשאות לכל תכנית. חלופות הן דיווח מובנה, CSV או הזנה ידנית | שלב 2 לפי שימוש |
| Telegram / WhatsApp / Gmail / Calendar / Drive | תיוג כערוץ, טריגר או יעד של אוטומציה. מדד פעילות רק ממקור מורשה שהוגדר לו שימוש | מיפוי מהאוטומציה או דיווח ייעודי. חיבור ישיר לחשבון דורש צורך והרשאה נפרדים. בשלב הראשון אוספים מטא־דאטה תפעולי | שלב 2 לפי שימוש |
| שירות פרטי / Cron / בוט מקומי | שם שירות, סביבה, מזהה ריצה, סטטוס וזמני התחלה וסיום | קליטת אירוע חתום או heartbeat. רישום ידני עם קישור זמין גם כשאין ממשק מכונה | MVP לקליטה בסיסית |

לכל מחבר מוצג מה זמין בפועל בחשבון זה: מלאי, אירועים, מדדים וכיסוי סביבות. ״מלאי בלבד״ ו״טרם דווח״ הם מצבי מידע גלויים. קצב דיווח ומשמעות שדה סטטוס נשמרים לפי ספק. ההחלטה אילו כלי אוטומציה להוסיף אחרי ה־MVP תתבסס על רשימת המקורות בפועל.

### תהליך חיבור ושיוך

1. בוחרים מרחב, ספק וחשבון. בודקים הרשאה ומציגים מראש משאבים שניתן לקרוא. בחיבור שמאפשר הרשאות נרחבות יותר, מסמנים מה נותן הספק ומה המוצר צורך בפועל.
2. מאשרים רשימת משאבים לסנכרון. בסנכרון הראשון מייבאים מלאי ועד 30 ימים של היסטוריה זמינה. מציגים מה הושלם ומה חסר.
3. מציעים שיוך לפי קישור רשמי בין ספקים או התאמה יציבה של מזהי פרויקט וריפוזיטורי. לדוגמה, פרויקט Vercel שמקושר לריפוזיטורי שכבר שויך. התאמת שם לבדה מוצגת כהצעה לבדיקה.
4. שיוך ידני גובר על הצעה אוטומטית ונשמר בסנכרון הבא. נכס שמשותף לכמה פרויקטים באותו מרחב מופיע בכולם ומקבל ספירה אחת בסקירה. נכס משותף לעולם אינו פותח גישה בין מרחבים.
5. אם סנכרון חלקי או אובדן הרשאה מעלימים נכס, שומרים את המידע האחרון עם תווית. רק אימות מפורש ממקור סמכותי, או היעדרות מאומתת בסנכרונים מלאים כשהיקף ההרשאה נשמר, מסמנים ״הוסר במקור״.

## 5. הגדרת סטטוסים ומדדים

| שדה | פירוש |
|---|---|
| מצב הנכס | כפי שדווח על ידי המקור, לדוגמה Workflow פעיל, פריסה בבנייה או פרויקט מושהה |
| מצב הביצוע האחרון | הצלחה, כשל, בתהליך, בוטל או אין דיווח. נקבע לפי זמן אירוע אצל הספק |

| כשל בפרויקט | אינדיקציה מתעדפת נכס קריטי בכשל בסביבת ייצור. כשל ב־Preview מופיע בפעילות ומסווג בנפרד |
| שיעור הצלחה | הצלחות מתוך ביצועים שהסתיימו בהצלחה או בכשל בחלון שנבחר. מציגים גם גודל מדגם וכיסוי מקור |
| זמן שנחסך | מדד אופציונלי. מספר ריצות מזכות כפול אומדן דקות שהוגדר לפריט. מסומן כהערכה |
| ריצה שלא הגיעה | זוהה רק לנכס עם תדירות או heartbeat מוגדרים, אחרי חלון חסד ובתנאי שהחיבור עצמו מעודכן |

פריסה מוצלחת מודדת את תהליך הפריסה. מדידת זמינות אפליקציה דורשת בדיקה ייעודית. תוצאת סנכרון חלקי תציין אילו נתונים עודכנו ומאיזה זמן מגיעים יתר הנתונים.

## 6. מבנה נתונים ומימוש מוצע

אפשר לממש עם Next.js ו־TypeScript על Vercel, ו־Supabase עבור Postgres ואימות. פעולות הרקע יופעלו ממתזמן ותור עמיד שמפרידים בין ספקים וחשבונות. בחירת מנגנון התור ותדירותו תלויה בתשתית ובמכסות בפיילוט.

| ישות | שדות עיקריים |
|---|---|
| workspace / membership | מזהה מרחב, משתמש, תפקיד |
| project | מזהה מרחב, שם, בעלים, חשיבות, סטטוס |
| connection / sync_job | ספק, מזהה חשבון/מופע, הפניה לסוד, יכולות, סמן המשך, תוצאת ניסיון |
| asset / project_asset | מזהה חיצוני, סוג, חשבון מקור, סביבה, קישור, מצב, שיוך לפרויקט ומקור השיוך |
| work_session | פרויקט, מקור הסשן, מזהה חיצוני אם זמין, בעלים, מטרה, זמן וסטטוס |
| activity_event / session_event | חיבור, נכס, מזהה אירוע, סוג, זמן במקור, זמן קליטה, תוצאה וקישור אופציונלי לסשן |
| alert / audit_event | מרחב, כלל/פעולה, יעד, מבצע, זמן ותוצאה |

- **קליטה.** כל מחבר מצהיר על יכולות ומנרמל רשימת שדות מותרת. יעד התחלתי לסנכרון פעילות הוא כל 15 דקות, ומלאי מלא פעם ביממה. webhook מאיץ קליטה כשנתמך. הסנכרון המחזורי משלים אירועים חסרים.
- **זהות וסדר אירועים.** מזהה נכס נקבע לפי מרחב, חיבור, סוג ומזהה חיצוני. מזהה אירוע ייחודי כולל ניסיון ריצה כשהספק מבחין בין ניסיונות. קליטה חוזרת מעדכנת את אותה רשומה. אירוע שמגיע באיחור נשמר בהיסטוריה ומעדכן תמונת מצב רק אם הוא עדכני יותר לפי סדר המקור.
- **התאוששות.** Pagination, שמירת cursor אחרי commit, retry מדורג בהתאם ל־Retry-After, ונעילה לחיבור כדי למנוע סנכרונים מתחרים. כשל בספק אחד משאיר את שאר הסנכרונים פעילים. reconciliation תקופתי בודק שלמות בלי להסתמך על webhook יחיד.
- **גבול הרשאות.** הגבלת קריאה דרך API ו־RLS עם מזהה מרחב בכל ישות וקשרים שחוסמים שיוך בין מרחבים. מנהל מחבר ומנתק. עורך משייך ומנהל סשנים. צופה רואה את הנתונים המורשים בלבד.
- **נתונים וסודות.** אחסון סודות מוצפן עם גישה לתהליכי שרת בלבד. השדות הנשמרים עוברים allowlist לפני אחסון או לוגים. הסנכרון יאסוף מזהים, זמנים, שמות וסטטוסים. תוכני prompt, תמלילים, payloads גולמיים, לוגי בנייה מלאים, משתני סביבה, תכולת DB ותוכן הודעות מחוץ לשדות האיסוף.
- **מדווחים חיצוניים.** חתימת HMAC, מגבלת זמן, מזהה אירוע ייחודי, מניעת replay וקצב בקשות מוגבל. חיבור n8n פרטי יכול להשתמש במדווח יוצא. חיבור API ישיר מוגבל לכתובות מאושרות וכולל בקרת יעדים ו־redirects.
- **ניתוק ושמירה.** ניתוק עוצר קליטה, מסיר או מבטל את האסימון לפי יכולת הספק ומסמן את העותק האחרון כלא עדכני. ברירת מחדל מוצעת לפיילוט היא 90 ימי פעילות, עם מחיקת היסטוריה לפי מדיניות מרחב. קטלוג וסיכומי סשנים נשמרים לפי מדיניות המרחב.
- **דמו.** פריסה ומקור נתונים נפרדים עם נתונים סינתטיים, כתובות דמה ותרחישים לבדיקת מסכים. לדמו אין גישה לתשתית הפרטית או לחשבונות מחוברים.

## 7. דוגמה לתצוגה בפועל

במרחב ״קומקס״ נכנסים ל״שילוט COMAX״ ופותחים סשן ״ארגון משתני מחיר ומבצע״. הריפוזיטורי comax-design מופיע בקטלוג לאחר אישור חיבור ושיוך. אם קיים פרויקט Vercel מקושר, מסך הפרויקט יציע לצרף אותו. בפעילות הסשן אפשר לראות PR, ריצת בדיקות ופריסת Preview, ולפתוח כל פריט במקור. פריסת Production תופיע גם אם נוצרה מחוץ לסשן, תחת פעילות הפרויקט. BuildFlow וקליניקת אפרת הן דוגמאות לפרויקטים נפרדים. הפריסות, מסדי הנתונים ונתוני הריצות בדוגמה תלויים במקורות שיחוברו בפועל.

## 8. שלבי מסירה וקריטריוני קבלה

**שלב 0 — מיפוי חיבורים.** בוחרים מרחבים וחשבונות ומאמתים הרשאות לקריאת משאב אחד ולקריאת פעילות אחת בכל ספק. רושמים לכל חיבור אם יש כיסוי מלא, חלקי, ידני או חסום. תוצר השלב הוא רשימת מקורות מאושרת.

**שלב 1 — MVP.** סקירה, קטלוג, פרויקטים, סשנים ידניים, מרכז חיבורים, תיבת מיון ופעילות. מתחילים ב־GitHub, Vercel ו־Supabase. n8n נכלל אם נמצא מופע פעיל ומורשה, עם חלופת אירועים חתומים או מלאי חלקי. דמו נפרד מדגים שיוך, כשל וחיבור חלקי.

**שלב 2 — מעקב עבודה שוטף.** פיילוט מדווחי Claude Code/Codex, שיפור קישור PR ופריסה, התראות מותאמות והרחבה לכלים שזוהו בשלב 0.

| בדיקה | תוצאה נדרשת |
|---|---|
| חיבור ספק עם שני חשבונות או ארגונים | מוצגים רק החשבונות והמשאבים שאושרו למרחב. לכל חיבור מדדי כיסוי נפרדים |
| ייבוא חוזר ו־webhook חוזר | אין נכסים או ריצות כפולים. שיוך ידני ותיאור שהוזן נשמרים |
| כשל באמצע pagination | המידע האחרון נשמר. מוצג כיסוי חלקי. המשך הסנכרון משלים את הרשומות |
| סגירת שני סשנים שעבדו על אותו ענף | אירוע ללא מזהה חד־משמעי נשאר להצעת שיוך |
| פריסה מוצלחת בייצור וכשל ב־Preview | שתי התוצאות מוצגות לפי הסביבה שלהן ומצב הייצור נשמר |

| דיווח חיצוני עם חתימה שגויה או חוזרת | הבקשה נדחית או מוכרת ככפילות, ואין רשומה נוספת |
| משתמש לקוח או דמו מנסה לגשת לקישור פרטי | ההרשאה נדחית גם בבקשה ישירה ל־API, בלי חשיפת מטא־דאטה |

## 9. משרד עבודה מלא — כלים, עלויות והרצת סוכנים

### 9.1 פרויקט כעמדת עבודה

| לשונית | מידע | פעולה |
|---|---|---|
| סקירה | בעלים, מרחב, סביבה, הוצאות החודש, ניצול תקציב, חריגות וריצות אחרונות | עריכת שם, תיאור, בעלים וסיווג. שינוי מרחב דרך אשף העברה נפרד |
| כלים ומפתחות | כל כלי בפועל, חשבון/ארגון, משאבים משויכים, מצב חיבור, הרשאות, יעד וקישור מקור | חבר כלי מאושר, החלף שיוך, פתח ישירות בפרויקט הספק או בדף ההגדרות המתאים |
| עלויות | פירוט לכל ספק, שירות, פרויקט ספק, סביבה, סשן וסוכן ככל שהנתונים מאפשרים | בחר תקופה, עבור לחיוב בודד, ערוך תקציב וכללי הקצאה |
| סוכנים | סוכנים ייעודיים וסוכנים כלליים הזמינים לפרויקט, יכולות, מצב וריצות | יצירה, עריכה, שינוי שיוך, השהיה, הפעלה וצפייה בתוצאה |

שינוי שיוך בתוך מרחב חל מרגע השמירה. היסטוריית עלויות וריצות שומרת את השיוך, גרסת ההגדרה והמפתח שהיו בתוקף בעת השימוש. שיוך משאב של ספק מותר רק אם החיבור רואה אותו ומורשה במרחב. העברה בין מרחבים דורשת הרשאה בשניהם, תצוגה מקדימה של ההשפעה, בחירת מפתחות וחיבורים חדשים וטיפול נפרד בהיסטוריה. סודות והרשאות לעולם אינם עוברים עם השיוך. שמירה נרשמת ביומן הביקורת. קישורי מקור מגיעים ממטא־דאטה מאומת או מתבנית ספק, ללא מפתחות או טוקנים בכתובת.

### 9.2 זהות והרשאות מול ספקים

״טוקן״ מופיע בשני הקשרים. **מפתח גישה** מזהה איזה חשבון והרשאה משמשים את הפרויקט. **טוקני שימוש** הם יחידות מדידה לצריכת מודל. במסך מוצגים בנפרד שם חיבור, חשבון ספק, מזהה מפתח, סיומת ממוסכת, הרשאות, סטטוס, מועד שימוש אחרון והפרויקטים והסוכנים שמשתמשים בו. מפתח אמיתי נשמר בכספת שרת. הרשאת חיוב, הרשאת ביצוע והרשאת קריאה לתשתית מופרדות.

- בוחרים מפתח ברירת מחדל לפרויקט. אפשר להגדיר חריגה לסוכן מתוך מפתחות שמותרים באותו מרחב ופרויקט. לפני הרצה מאמתים מחדש את היקף המפתח ואת התאמתו לספק ולמודל.
- החלפה או סבב מפתחות מציגים מראש אילו פרויקטים, סוכנים וריצות מושפעים. שומרים גרסה חדשה רק אחרי בדיקת חיבור. ריצה שממתינה מוערכת מחדש בעת ההפעלה, וריצה שהתחילה שומרת תיעוד של גרסת ההגדרה. ביטול גישה חוסם גם צעדים עתידיים בריצה קיימת.

### 9.3 עלות אמיתית לכל פרויקט

| סוג סכום | מקור ושיוך | איך מוצג |
|---|---|---|
| חיוב מדווח | API חיוב, חשבונית או ייבוא מורשה, משויך לפי מזהה פרויקט אצל הספק כשזמין | תקופה, ספק, מטבע מקורי, מועד קליטה וקישור לאסמכתה |
| שימוש AI | חשבון ספק, פרויקט, מפתח, מודל וריצה לפי ממדים שהספק מחזיר או לפי דיווח מקומי | קלט, פלט, קלט מהמטמון כשזמין, ויחידות נוספות לפי מודל. שימוש שחסר מסומן כחסר |
| אומדן | יחידות שימוש כפול תעריף בגרסה שהייתה בתוקף, כולל כלי מודל כשנמדדו | תווית אומדן, בסיס החישוב ומועד התעריף |
| הקצאה משותפת | חיוב חשבון משותף שמחולק באחוזים, סכום קבוע או מדד מוסכם | כלל חלוקה, תאריך תחולה ויתרה שלא שויכה |
| מנוי חיצוני | חשבונית או הזנה ידנית כשאין מקור קריא | סכום ותקופה. הצריכה לפי פרויקט נשארת חסרה אם אין מדידה |

עלות פרויקט מוצגת לצד מידת הכיסוי. סכום מאוחד מציין אם הוא כולל אומדנים. כשאותו שימוש מקבל חיוב מאומת, האומדן מוחלף בסכום הכולל ונותר זמין בהיסטוריית ההתאמה. משווים רשומות לפי ספק, חשבון, חלון זמן ומזהה ריצה או מזהה חיוב זמין, עם התאמה ברמת הקיבוץ שהספק מספק. לא משייכים חשבון משותף לפרויקט לפי שם בלבד. מטבע מקורי נשמר. בהמרה מציגים מקור ותאריך שער, ומציגים בנפרד מע״מ, זיכויים ועלויות שטרם נקלטו. מגדירים תקציב לפי פרויקט, התראה מוקדמת ותקרת הרצה פנימית. הסכומים בדמו סינתטיים.

### 9.4 מרכז הסוכנים

סוכן כללי נוצר במרחב וניתן להפעלה על פרויקט מותר שנבחר במפורש. סוכן ייעודי רץ רק בפרויקט שלו. יצירת סוכן כוללת שם, הוראות, בעלים, מודל וספק, מפתח מורשה, רשימת כלים, פרויקטים מותרים, מגבלת צעדים, זמן, טוקנים ועלות, וכלל אישור לפעולות. שמירה יוצרת גרסת הגדרה. בסקירה כללית אפשר להפעיל סוכן פעם לכל פרויקט נבחר, עם תוצר, הרשאות וחיוב נפרדים לכל ריצה.

1. **הגדרה.** בוחרים מטרה, שיוך וכלים. ברירת המחדל היא פעולות קריאה. פעולה שמשנה מערכת חיצונית דורשת יכולת ייעודית, הרשאה מצומצמת ואישור של הפעולה והיעד. המודל אינו יכול להרחיב את היקף ההרשאה.
2. **הרצה.** בוחרים פרויקט וסשן אופציונלי, בודקים הרשאה, תקציב ומגבלות ומכניסים לתור. השרת קובע מזהה ריצה ייחודי ומשקלל גם ריצות מקבילות בבדיקת התקציב. לחיצה כפולה לא תיצור ריצה נוספת.
3. **מעקב.** מצבים: ממתין, רץ, ממתין לאישור, הושלם, נכשל, בוטל. במסך הריצה רואים את ההגדרה, הכלים שנקראו, תוצאה, שגיאות, פעולות שאושרו, צריכה ועלות. ביטול עוצר שלבים עתידיים ומציג פעולות שכבר הושלמו. כשל חוזר רק בצעדים שניתן לבצע שוב בלי לשכפל תוצאה.
4. **תוצרים.** תוצר נקשר לפרויקט ולסשן, ויכול להיות סיכום מצב, בדיקת חריגות או דוח. הרשאות התוצר הן של פרויקט היעד. תזמון וטריגרים מאירועים נכנסים בשלב המשך עם כללי אישור ומכסות ייעודיים.

### 9.5 מסירה ובדיקות לגרסת המשרד

- לאחר הקטלוג והסנכרון הבסיסיים, מוסיפים שיוך חיבורים ומפתחות, קישורי מקור ופנקס עלויות עם מקור לכל שורה. לאחר מכן מוסיפים מנוע סוכנים בקריאה בלבד, עם הפעלה ידנית ומסך ריצה. פעולות כתיבה מאושרות ותזמון נמסרים אחרי שהרשאות, תקרות ועלויות נבדקו.
- החלפת מפתח בפרויקט משנה את ברירת המחדל לריצות חדשות ששואבות את ברירת המחדל. חיוב היסטורי וריצה קודמת נשארים עם המזהה המקורי. ניסיון לשייך מפתח ממרחב אחר נדחה בצד השרת.
- חיוב מדווח שמגיע אחרי אומדן אינו נספר פעמיים. חיבור ללא מידע חיוב מציג ״חסר מידע״. עבור הוצאה משותפת אפשר לעבור מהסכום לכלל ההקצאה.
- סוכן כללי לא יכול לרוץ בפרויקט שלא אושר. סוכן מושבת לא ניתן להפעלה. ריצה שדורשת פעולה חיצונית מושהית עד אישור וכוללת תיעוד של המפעיל, היעד והתוצאה.
- במוקאפ, הרצה מדומה יוצרת רשומת ריצה, תוצר ועלות משוערת ומקשרת למפתח ולפרויקט. במימוש, קריאות המודל והכלים עוברות דרך שרת ותור מורשים.
