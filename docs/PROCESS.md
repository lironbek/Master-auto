# איך התהליך אמור לעבוד — ההבנה שלי

מסמך זה מחבר את שני האפיונים (מרכז הבקרה v2 וסוכן ה-PT v1.1) לתהליך אחד,
ומתאר איך המערכת שנבנתה ממשת אותו ומה נשאר לשלב הבא.

## 1. הבעיה שהמערכת פותרת

יש לך כ-80 ריפוזיטוריז, כ-80 פרויקטים ב-Vercel ו-16 פרויקטים ב-Supabase, לצד
אוטומציות (n8n) ושירותים פרטיים. הם מתפזרים על שני מרחבים: עבודה בקומקס
(`comax-*`, `AnibTech`) ופרויקטים פרטיים (BuildFlow, DealHunters, Corewise,
NeveMichael ועוד). השאלות היומיומיות הן "מה קיים", "מה כל רכיב עושה", "איפה הוא
רץ", "מה נכשל", "מה עלה החודש" ו"מה עשיתי בסשן האחרון". המערכת צריכה לענות על
כולן תוך פחות מדקה בלי לנהל את הקוד או את הפריסות במקום הכלים המקוריים.

## 2. מודל המידע בקצרה

```
ארגון  ──▶  מרחב (קומקס / פרטי / לקוח)  ──▶  פרויקט  ──▶  נכסים (ריפו, Vercel, Supabase, Workflow, שירות)
                                             │             └─▶ אירועים (פריסה, ריצת Actions, PR, ריצת Workflow, heartbeat)
                                             ├─▶ סשני עבודה (פרקי עבודה, ציר אירועים, תוצר)
                                             ├─▶ עלויות (חיוב מדווח / אומדן / הקצאה / מנוי) + מפתחות ספק
                                             ├─▶ סוכנים וריצות (קריאה בלבד, תוצר = סיכום מצב)
                                             └─▶ סקרי אבטחה (מודול PT: חוזה, היקף, ריצה, ממצאים, ראיות, דוח)
```

מרחב הוא גבול ההרשאות. נכס שייך למרחב אחד ולפרויקט אחד או יותר באותו מרחב.
שיוך ידני גובר על הצעה אוטומטית ושורד סנכרון.

## 3. מחזור החיים

### 3.1 הקמה (פעם אחת)
1. פותחים מרחבים: "קומקס" (עבודה) ו"פרויקטים פרטיים". לקוח שדורש הפרדה מקבל מרחב משלו.
2. מחברים ספקים לכל מרחב: GitHub (ארגון / ריפוזיטוריז נבחרים), Vercel (צוות),
   Supabase (ארגון), n8n (מופע). המערכת מאמתת הרשאה לפני השמירה ומציגה מה
   היא תקרא בפועל. הטוקן נשמר מוצפן ולא חוזר.
3. סנכרון ראשון מייבא מלאי ו-30 יום של היסטוריה. כל נכס חדש נכנס לתיבת המיון.
4. בתיבת המיון משייכים נכסים לפרויקטים. הצעות מגיעות מקישור יציב (פרויקט Vercel
   שמקושר לריפו שכבר שויך), לא מדמיון שם.

**מה כבר נעשה:** הקטלוג נזרע מהמלאי האמיתי שלך (ראו `docs/inventory/`):
כל ריפו, פרויקט Vercel ו-Supabase קיבל נכס, הנכסים קובצו לפרויקטים לפי שם המוצר
(`buildflow-app` + `buildflow` + ריפו `buildflow-app` → פרויקט `buildflow`),
והפרויקטים חולקו למרחבים לפי כלל `comax`/`AnibTech` → קומקס. כשתחבר את
הספקים בפועל, אותם מזהים חיצוניים ייתפסו על ידי החיבור והנתונים יתעדכנו.

### 3.2 שוטף (כל 15 דקות, אוטומטי)
- ה-cron מסנכרן כל חיבור. אירוע שחוזר מעדכן את אותה רשומה; אירוע ישן יותר לא
  דורס תמונת מצב חדשה. נכס שלא חזר בסנכרון מלא מסומן "הוסר במקור".
- כשל בייצור על נכס משויך → התראה. 45 דקות בלי סנכרון תקין → "לא עדכני".
- שירות בלי API מדווח בעצמו (heartbeat חתום עם מזהה ייחודי; כפילות מזוהה).

### 3.3 עבודה יומית
- **סקירה**: פרויקטים פעילים, חריגות, סשנים פתוחים, ממתינים לשיוך, טריות.
- **פרויקט**: לשונית סקירה (תקציב וניצול, פריסה אחרונה, פעילות), נכסים, סשנים,
  כלים ומפתחות (קישורי מקור, מפתח ברירת מחדל), עלויות, סוכנים, סקרי אבטחה.
- **סשן**: פותחים מתוך פרויקט עם כותרת ומטרה. אירועי הפרויקט מוצעים לשיוך;
  שיוך ידני בלבד. בסגירה: תוצר, קישורים, המשך טיפול.
- **סוכן**: מגדירים פעם אחת (מודל, מפתח, פרויקטים מותרים, מגבלות). הרצה על
  פרויקט אוסף קטלוג, אירועים, סשנים, עלויות והתראות, ומפיק סיכום מצב. כל ריצה
  נרשמת עם צעדים, שימוש ועלות משוערת שנכנסת לפנקס העלויות.
- **עלויות**: חיובים מדווחים נוספים ידנית או מייבוא; אומדנים מגיעים מריצות.
  סכום מאוחד מסמן אם הוא כולל אומדנים.

### 3.4 סקר אבטחה (מודול PT)
מתוך פרויקט → "סקרי אבטחה" → קישור/יצירת סקר. משם: מסמך הרשאה, היקף מאושר,
ריצה חיה עם מנוע מדיניות ואכיפת יעדים, ממצאים עם ראיות מושחרות, דוח. ההיגיון
המלא ב-`docs/PT_Agent_PRD_HE.md` ו-`docs/PT_ARCHITECTURE.md`.

### 3.5 שימוש לפי לקוח (API, הודעות, OCR)

כל קריאה בתשלום שאינטגרציה מבצעת עבור לקוח (Claude / Gemini / OpenAI, עמודי OCR,
הודעות WhatsApp ולכמה נמענים) מדווחת כרשומת שימוש: ספק, מדד, כמות, הממשק שביצע
(n8n/<workflow>, בוט, אפליקציה), הלקוח והפרויקט. הדיווח נעשה מהאינטגרציה עצמה
(`POST /cc/usage` עם טוקן הדיווח של המרחב), כי רק היא יודעת עבור מי בוצעה הקריאה;
ריצות סוכנים כאן מדווחות אוטומטית. המסך "שימוש לפי לקוח" מציג לתקופה: לפי לקוח
(עם פירוט לפי ספק וממשק), לפי ממשק, לפי ספק ופרויקט. פרטים ב-`docs/USAGE.md`.

### 3.6 פעולות על המקור (ארכוב / מחיקה של ריפוזיטורי)

מעמוד הנכס של ריפוזיטורי GitHub, מנהל מרחב יכול לארכב או למחוק את הריפוזיטורי
במקור. זה מכוון להיות קשה: הקלדת השם המלא, אישור נוסף, טוקן חיבור עם Administration:
write (סנכרון רגיל לא דורש זאת), ורישום ביומן הביקורת לפני ואחרי. הסנכרון עצמו
לעולם לא משנה דבר אצל הספק; זו היכולת היחידה שכותבת למקור, והיא מפורשת.

### 3.7 צלילה לפרויקט: "איך הוא בנוי" וסריקות

בעמוד הפרויקט, הלשונית "איך הוא בנוי" אוספת דרך החיבורים (קריאה בלבד) את המבנה של
כל נכס: בריפו — שפות, מסגרת, תלויות, אינטגרציות שזוהו, מבנה תיקיות, CI, בדיקות,
מיגרציות, README; ב-Vercel — מסגרת, Node, ריפו מקושר, ענף ייצור, שמות משתני סביבה
(לא ערכים), כתובות, פריסת ייצור אחרונה, cron; ב-Supabase — טבלאות עם מצב RLS ואומדן
שורות, policies, גרסה. מזה נבנה סיכום ארכיטקטורה דטרמיניסטי שגם הסוכנים מקבלים.

הלשונית "סריקות" מריצה סריקת תקינות שמחזירה ממצאים עם חומרה ותיקון מוצע: הגנת
ענף, התראות Dependabot / סודות / קוד, קובצי env בריפו, בדיקות ו-CI, lockfile, פריסה
אחרונה שנכשלה, סודות plain ב-Vercel, טבלאות ללא RLS. כל סריקה נשמרת (ציון A/B/C)
להשוואה לאורך זמן. "סריקת קוד" שולחת ל-Claude עד 25 קבצי מקור רלוונטיים לאבטחה מכל
ריפו (אחרי השחרת סודות, דרך מפתח ה-Anthropic של הפרויקט או השרת) ומחזירה ממצאים עם
קובץ ושורה; השימוש נזקף ללקוח של הפרויקט. סריקת אבטחה של האתר החי נעשית במודול
סקרי האבטחה.

### 3.8 התראות החוצה

כל התראה חדשה (כשל בייצור, עיכוב סנכרון, הרשאה) וכל סריקה שמקבלת ציון C נשלחות
גם החוצה אם הוגדר: `CC_ALERT_WEBHOOK_URL` (POST JSON לכל יעד, למשל n8n/Slack) ו/או
אימייל דרך Resend (`RESEND_API_KEY`, `CC_ALERT_EMAIL_TO`, אופציונלי `CC_ALERT_EMAIL_FROM`).
כשל במשלוח נרשם ביומן הביקורת.

## 4. עקרונות שנאכפים בקוד

| עיקרון | איפה |
|---|---|
| מרחב = גבול הרשאות; צופה רואה רק מרחבים שלו | `cc/service.py::require_workspace`, בדיקת `test_workspace_isolation_and_roles` |
| קריאה בלבד מהספקים, allowlist של שדות | `cc/connectors/*`, בדיקת `test_github_inventory_prs_runs_allowlisted_fields` |
| סודות מוצפנים, לא חוזרים מה-API | `cc/secrets.py`, `test_connection_requires_secret_key` |
| ייבוא חוזר לא מכפיל | מפתחות ייחודיים ב-`0003`, `test_full_flow_connection_sync_inbox_assign_session_cost` |
| שיוך לפי זמן בלבד אסור | `routes.py::get_session` (הצעות בלבד) |
| סוכן לא יכול להרחיב הרשאה | `tools=["catalog.read"]`, `test_keys_agents_and_runs` |
| מפתח ממרחב אחר נדחה בשרת | `routes.py::create_agent` |

## 5. מה חסר לגרסה הבאה (לפי סדר ערך)

1. **מחברי Claude Code / Codex**: hook מקומי שמדווח פתיחה/סגירה של סשן עם
   ריפו וענף (ללא תוכן שיחה) לנקודת `/cc/report` עם מזהה סשן. היום סשן נפתח ידנית.
2. **חיוב מדווח אוטומטי**: ייבוא מ-Usage/Cost API של Anthropic ו-OpenAI לפי מפתח.
3. **פעולות כתיבה לסוכנים** עם אישור של הפעולה והיעד, ותזמון ריצות.
4. **אשף העברה בין מרחבים** עם תצוגה מקדימה של ההשפעה.
5. **דמו נפרד** על נתונים סינתטיים (המוקאפ קיים ב-`docs/`).
